## What it is

AI Workshop is a proposed after-school club for students aged 13 and over who code, or want to. It teaches them to work with the AI coding tools that professional developers now use: choose the right tool, use it well, and check what it gives back. Students with a parent or guardian's consent for tools that require it can take part. Students under 18 need that consent for any tool that requires it.

## The gap

Students are taught Python, which is fundamental and current. But they are not taught how the newest AI coding tools work, which one to reach for, or how to tell when the answer is wrong. They are using these tools anyway, mostly on their own, with no habits to guide them.

## Three ideas behind the club

1. Built on what the school teaches. The school teaches the fundamentals, Python included. The club adds the newest AI tools, demonstrated and used on students' own projects, plus git by hand.
2. The toolbox has grown. Professional teams already work with AI coding assistants. Like any toolbox, the value is in knowing what each tool is for.
3. Judgment is the skill. Knowing when to push back on a tool is the skill. Students read, test, question and decide. The student stays in charge. This is the human in the loop: the AI drafts, a person decides.

## Right tool for the job

Different AI tools are good at different things. For example: ChatGPT for drafting writing, Gemini for research on what Google indexes, Copilot inside Microsoft Office, Perplexity for research with sources to check, NotebookLM for studying from your own notes, and coding tools such as Codex and Claude Code for working inside a project. Students test these on their own tasks and decide. One free tool, DeepSeek, is used as an example of why to check where your data goes before you type anything personal.

## What students learn

- Know the toolbox: what AI students already use, the right tool for each job, and the right and wrong way to code with AI.
- Git, the developer's safety net: how version control works, then the commands typed by hand. Branches, history, undoing mistakes, keeping secrets out of a project.
- An AI coding tool, then checking its work: set one up in their own project, then use it to review changes, find bugs, write tests and spot security problems.
- How software really gets built: the development life cycle, traditional and AI-assisted, then a real project of their own from spec to working code.
- Judgment, then agents: keys, privacy, integrity and licensing, and finally a small AI agent built on top of working code.

## Guardrails

- Students use only tools they are old enough to use, with parent or guardian consent where a tool requires it.
- Some tools are for 18 and over, so the trainer demonstrates those, and students who are 18 can use them.
- Everything the AI writes is read, tested and understood before it is used. If a student cannot explain the code, it is not finished.
- Students type git commands themselves before any tool is allowed to run them.
- No passwords, keys or personal data go into an AI tool or a code repository.
- The school decides which tools are allowed and how the club fits its integrity and safeguarding rules.

## The proposal

Students aged 13 and over who code or want to, and hobby builders. Roughly 5 to 10 per club. About an hour a session, with frequency and length set by the school. Students bring their own projects, and a starter project is available for anyone without one. The club is led by Mark Tenzer, who runs similar AI workshops for university students. The next step is a conversation about timing, equipment and which tools the school allows.
